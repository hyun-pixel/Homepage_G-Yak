# G-야크 홈페이지 디자인 명세서

수정일: 2026년 10월 15일 · 버전: 1.6 · 상태: 전체 문구·배치 정리 및 PC·모바일 최종 검수 완료

최신 적용 범위는 화면 18이다. [쇼핑 경험 확장](EXPANSION_V14.md)과 이 문서의 마지막 절을 함께 따른다. 번호가 붙은 이전 제작 기록은 해당 버전의 이력이며 최신 범위를 제한하지 않는다.

이 문서는 G-야크를 **어떤 모습과 동작으로 만드는지** 정리한다. 사용자가 선택한 생활형 방향과 기능을 바탕으로, 구현에 필요한 세부 값을 제안한다. 수치·문구·상품명·로고 형태는 대표 시안에서 확인하고 수정할 수 있다. [PRD](PRD.md)의 R01부터 R12를 같은 번호로 참조한다. 쇼핑몰 조사 근거·적용 원칙은 [확장 기록](EXPANSION_V14.md)에 연결한다.

## 1. 디자인 방향과 레퍼런스

선택한 방향은 **편안한 생활형 아웃도어**다. 밝은 회색과 차분한 올리브, 자연광의 착용 사진, 단정한 한글로 편안함·일상성·자연스러움을 전달한다. 고객이 “나도 평소에 이렇게 입을 수 있겠다”고 느끼게 한다. 전문 등반 장비나 할인 행사보다 실제 생활에 어울리는 모습이 우선한다. (R01, R10)

영상에서 가져올 원칙은 제품을 크게 보여주기, 제품이 화면에 머무르는 동안 설명 이어가기, 위치·크기 변화로 초점 바꾸기, 충분한 여백, 고정 메뉴다. 푸른 색감·원본 문구·로고·상품 사진·기술 수치는 복제하지 않는다. 레퍼런스의 실제 모바일 웹이나 클릭 동작, 렌더링 기술은 확인하지 못했다. 모바일 구성과 색상 선택은 새로 설계한다. (R02, R03)

사진을 주인공으로 두고 글자는 짧게 사용한다. 홈은 제품 중심 몰입, 넓은 생활 사진, 상품 비교, 짧은 브랜드 메시지로 리듬을 바꾼다. 상품 목록·상세·주문 화면은 감상보다 정보와 조작이 먼저다.

초기 대표 시안은 밝은 단일 테마로 제안한다. 자동으로 어두운 테마로 바뀌어 사진과 브랜드 인상이 달라지지 않게 한다. 이는 밝은 생활형 선택을 구체화한 제안이며 다크모드 기능은 초기 범위에 추가하지 않는다.

## 2. 디자인 시스템과 공통 값

**디자인 시스템**은 화면마다 같은 규칙을 쓰기 위한 색상·글자·배치·버튼의 약속이다. **디자인 토큰**은 이 약속에서 반복 사용하는 이름 붙은 값이다. 예를 들어 `color.action`은 모든 중요한 버튼에 적용할 같은 올리브색이다. 아래는 제작 제안값이며 실제 콘텐츠를 넣은 시안에서 최종 조정한다.

### 2.1 색상

| 토큰 | 제안값 | 적용 위치와 역할 |
|---|---|---|
| `color.background` | `#F2F4EF` | 기본 페이지 배경, 밝은 회색 |
| `color.surface` | `#FBFCF9` | 입력 필드, 드로어, 밝은 정보 영역 |
| `color.hero-start` | `#E2E7DA` | 히어로의 차분한 올리브 회색 |
| `color.hero-end` | `#F1F3ED` | 히어로 배경의 밝은 끝색 |
| `color.text` | `#263024` | 제목·본문·가격 |
| `color.text-muted` | `#5C6656` | 보조 설명·상품 옵션·비활성 회원 항목 |
| `color.hero-copy` | `#4C5747` | 히어로 사진 위 설명. 사진 없는 화면의 보조 글자보다 짙게 사용 |
| `color.action` | `#4C5B45` | 주요 버튼·선택 표시·브랜드 강조 |
| `color.action-hover` | `#3C4A37` | 주요 버튼에 마우스를 올린 상태 |
| `color.border` | `#D9DED4` | 정보 구분을 위한 얇은 선 |
| `color.input-border` | `#7D8776` | 입력 필드의 조작 경계 |
| `color.focus` | `#34462D` | 키보드로 선택한 요소의 테두리 |
| `color.success` | `#3E6044` | 옵션 반영·내역 확인 등 성공 안내 |
| `color.error` | `#A6403A` | 잘못 입력한 항목의 문장·테두리 |
| `color.warning` | `#875D29` | 필요한 경우 주의 정보와 설명 문장 |

페이지 전체에서 마케팅 강조색은 올리브 한 계열로 유지한다. 성공·오류 색은 상태에만 사용하고 장식이나 다른 섹션의 강조색으로 전용하지 않는다. 오류는 색과 함께 이해할 수 있는 문장을 표시한다.

제안값 계산 결과: 본문/기본 배경 12.39:1, 보조 글자/기본 배경 5.43:1, 밝은 버튼 글자/주요 버튼 7.06:1, 입력 경계/필드 배경 3.64:1, 포커스/배경 9.21:1이다. 일반 글자의 최소 4.5:1 기준은 [W3C 글자 대비 안내](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)를 따른다. 사진 위 글자의 대비는 실제 이미지로 별도 확인한다.

### 2.2 타이포그래피

**타이포그래피**는 글꼴·크기·굵기·줄 간격을 정하는 규칙이다. 예를 들어 G-야크의 큰 한글 제목은 부드럽게 읽히되, 가격과 옵션은 빠르게 찾을 수 있도록 다른 크기와 굵기를 쓴다.

한글·영문은 **SUIT** 한 가족을 기본으로 제안한다. 영문 로고의 실제 글자 형태는 별도 시안으로 확인한다. SUIT의 웹폰트와 사용 조건은 [제작자 저장소](https://github.com/sun-typeface/SUIT/blob/main/.github/README.md) 및 [라이선스](https://github.com/sun-typeface/SUIT/blob/main/LICENSE)에 안내되어 있다. 제작 시 폰트 파일과 라이선스를 함께 보관하고 사이트 자체에서 제공한다. 대체 글꼴은 시스템의 한글 고딕체다.

| 역할·토큰 | PC | 모바일 | 굵기·줄 간격 |
|---|---:|---:|---|
| `type.hero` | 48–64px | 32–36px | 650, 1.15 |
| `type.story-title` | 40px | 28–30px | 650, 1.15 |
| `type.page-title` | 28px | 26px | 600, 1.25 |
| `type.subheading` | 24px | 20px | 600, 1.3 |
| `type.body` | 16–17px | 16px | 400, 1.6–1.7 |
| `type.ui` | 16px | 16px | 500, 1.4 |
| `type.support` | 14px | 14px | 400, 1.5 |

홈·브랜드의 이야기 제목과 상품 조작 화면의 제목을 구분한다. 상품 목록·상세·장바구니·주문 제목은 최대 28px로 억제한다. 히어로 제목은 자연스럽게 최대 2줄로 배치하고 한글 낱글자 단위의 어색한 줄바꿈을 막는다. 본문 폭은 PC 32em 이내, 모바일은 화면 여백 안에서 30자 안팎을 기준으로 확인한다.

본문 자간은 기본값, 큰 이야기 제목은 `-0.04em`, 짧은 영문 대문자는 `0.06em`을 제안한다. 가격은 숫자 폭을 일정하게 맞춘다. 제목과 이어지는 설명 사이에는 32px, 설명 문단 사이에는 16px을 둔다. 고정 높이로 글자를 잘라내지 않는다. 한글의 글자 윤곽을 고려한 줄 간격은 실제 폰트 시안에서 확인한다.

### 2.3 레이아웃·여백

**그리드**는 내용을 정렬하는 열과 간격의 기준이다. G-야크에서는 PC의 상품을 4열로 비교하고, 모바일은 2열로 줄이는 데 사용한다.

| 토큰 | 제안값 | 적용 |
|---|---|---|
| `layout.max-content` | 1280px | 기본 콘텐츠 최대 폭 |
| `layout.max-copy` | 32em | 긴 설명의 읽기 폭 |
| `layout.gutter` | PC 48px / 중간 32px / 모바일 20px | 화면 양옆 여백 |
| `layout.columns` | PC 12 / 중간 8 / 모바일 4 | 전체 배치 기준 |
| `layout.grid-gap` | PC 24px / 중간 20px / 모바일 12px | 사진·상품 간 간격 |
| `space.scale` | 4, 8, 12, 16, 20, 24, 32, 48, 64, 80, 96, 128px | 반복 간격의 선택 범위 |
| `space.section` | PC 96px / 중간 80px / 모바일 64px | 일반 섹션의 위·아래 여백 |
| `space.related` | 8px부터 16px | 이름·가격·옵션처럼 같은 정보 그룹 |
| `space.group` | 24px부터 32px | 다른 옵션 그룹·콘텐츠 블록 |
| `space.heading-copy` | 32px | 제목 다음 설명 |
| `space.label-input` | 8px | 입력 항목 이름과 해당 칸 |
| `space.field-group` | 24px | 다음 입력 그룹과의 간격 |

기본 왼쪽 정렬, 제품 중앙 배치를 병행한다. 히어로는 화면 전체에 배경을 두되 내용은 공통 양옆 여백을 따른다. 화면 상단의 헤더 공간을 예약하고 첫 내용이 헤더 아래로 숨지 않게 한다. 일반 섹션의 위·아래 여백은 같은 값을 사용한다. 선보다 여백으로 정보를 묶는다.

### 2.4 형태와 구성요소 토큰

| 토큰 | 값·규칙 |
|---|---|
| `control.height` | 기본 버튼·입력 48px, 버튼 글자 한 줄 유지 |
| `control.touch` | 최소 44 × 44px, 인접 누름 영역 사이 8px 이상 |
| `radius.button` | 999px, 부드러운 알약형 버튼 |
| `radius.media` | 12px, 사진 모서리 |
| `radius.field` | 8px, 입력 칸 |
| `radius.overlay` | 화면 가장자리 패널은 0px |
| `border.width` | 기본 1px, 선택 표시는 2px |
| `focus.ring` | 3px, 바깥 간격 3px, 즉시 표시 |
| `shadow.overlay` | 배경색 계열의 약한 그림자, 오버레이에만 사용 |
| `layer.order` | 본문 0 / 고정 헤더 20 / 덮개 40 / 드로어 50 / 상태 알림 60 |

기본 누름 영역은 WCAG의 절대 최소값보다 넉넉한 44px 이상을 자체 기준으로 제안한다. 공식 최소 기준과 예외는 [W3C Target Size 안내](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)에서 확인한다. 일반 상품 사진과 정보 묶음에는 두꺼운 카드 테두리나 그림자를 반복하지 않는다. 아이콘은 한 가족의 얇은 선 형태, 크기 20px부터 24px을 제안하고 기능 이름을 함께 제공한다.

## 3. 홈의 섹션별 명세

### 3.1 헤더 (R04, R06, R08, R09)

- 목적·우선순위: 브랜드 인식, 상품 이동, 장바구니 순. 구매 탐색이 항상 가능해야 한다.
- 내용: G-YAK 워드마크 제안, 전체 상품·아우터·상의·팬츠·용품·저널·브랜드, 검색·관심상품·장바구니 실제 담긴 수량, 비활성 회원가입·로그인·마이페이지.
- 배치: PC 높이 64px의 한 줄, 제품 이야기 위에서도 유지. 상품 선택을 가리는 별도 광고띠는 만들지 않는다.
- 연결: 로고는 홈, 각 상품 메뉴는 해당 목록, 브랜드는 브랜드 페이지, 장바구니는 드로어.
- 모바일: 높이 56px, 로고·메뉴 버튼·장바구니. 펼친 메뉴에 상품 분류·브랜드·비활성 회원 항목을 배치한다.
- 동작: 현재 페이지를 표시하고, 키보드 포커스나 이동 대상이 헤더에 가려지지 않게 여유를 둔다.

### 3.2 히어로와 제품 이야기 (R02, R03)

- 목적: 대표 경량 패딩의 형태를 감상하고, 도심과 바깥 풍경을 잇는 브랜드의 인상을 이해한다. 설산 배경은 분위기 표현이며 극한 등반용 성능을 주장하지 않는다. (2026-10-14 사용자 피드백 반영)
- 제안 제목: “매일의 움직임을 가볍게”. 본문: “출근길부터 주말의 산책까지. 일상에 자연스럽게 어울리는 G-야크의 경량 패딩.” 문구는 가상 브랜드의 창작 카피다.
- 자료: 에브리데이 라이트 다운의 기존 투명 배경 단독 이미지 3색, 같은 제품의 열린 모습 3색, AI 풍경 사진 3장(도심·설산·트레킹). 기존 이미지를 참조해 퀼팅·소매·후드·포켓·색을 이어간다. 열린 컷은 1000×1200 투명 WebP, 배경은 PC 1600×900·모바일 768×432 WebP다.
- 배치: PC 첫 장면은 제품을 중앙보다 오른쪽에 크게, 메시지는 왼쪽에 둔다. 상품명·색상·버튼은 하단의 밝은 가로 영역으로 모아 이동하는 제품과 분리한다. 중간·모바일은 메시지 위, 제품 가운데, 구매 조작 아래다. 모바일 하단 버튼은 가로 전체 폭이다.
- 높이: 첫 장면은 화면 높이를 기준으로 헤더 공간을 제외해 구성한다. 전체 소개 구간은 4단계, 약 4화면 분량을 시작 제안값으로 둔다. PC·모바일 모두 같은 4단계다.
- 우선순위: 제품 → 핵심 제목 → 색상 → 상세로 이동하는 버튼. 설명은 장면마다 짧게 바뀌며 자동으로 지나가지 않는다.
- 버튼: ‘제품 살펴보기’ → 대표 상품 상세. 선택 색상을 전달한다. 히어로에서 사이즈를 고르거나 장바구니에 바로 담지 않는다.
- 다음 구간: 마지막 색상 장면을 지나면 제품 고정이 풀리고 일상 착용 사진으로 이어진다. 임의 반복 재생이나 화면 맨 위로 되돌리는 동작은 넣지 않는다.
- 모바일: PC와 같은 이동·확대·축소를 유지한다. 글자는 제품에 겹치지 않게 위·아래에, 색상과 버튼은 닿기 쉬운 하단에 둔다. 화면에 담을 수 없는 짧은 높이·확대 환경에서는 내용 전체를 자연스럽게 스크롤해 읽을 수 있도록 고정을 풀 수 있다.

| 단계 | 핵심 메시지·사진 | PC 초점 | 모바일 조정 |
|---|---|---|---|
| 도심 | “매일의 움직임을 가볍게”, 도심 사진 | 제품 중앙에서 오른쪽 8vw, 설명 왼쪽 | 제품 중앙, 제목 위·색상 아래 |

스크롤을 강제로 바꾸지 않는다. 사용자 스크롤 진행률에 맞춰 제품의 위치·크기와 설명 상태가 변한다. 모든 색상 이미지가 준비되기 전에는 기존 이미지를 유지해 빈 제품 화면이 나타나지 않게 한다.

### 3.3 일상 속 착용 모습 (R01, R05)

- 목적·메시지: “내 일상에 어떻게 어울릴까?”에 사진으로 답한다.
- 제목 제안: “평일에도, 주말에도”. 본문은 “도시를 걷고, 잠시 밖으로 나가는 날에도 자연스럽게.”
- 자료: 성인 남녀 모델의 출근·산책·여행 사진. 단정한 보통 옷차림, 과한 등반 장비 없는 생활 장면.
- 배치: 넓은 출근 사진 1장과 크기가 다른 산책·여행 사진 2장. 사진을 같은 카드 3개로 반복하지 않는다.
- 우선순위: 전체 착용 인상 → 상황 설명 → 입은 상품 확인. 판매량·후기·유명인 추천을 근거처럼 넣지 않는다.
- 연결: 사진 자체와 사진 아래 링크로 착용 색상이 선택된 대표 패딩 상세에 이동한다. 출근 사진은 기본 올리브로 연결하고 아래에 ‘올리브 보기’·‘스톤 보기’를 함께 제공한다. 산책은 스톤, 주말은 차콜로 연결한다. 사진의 팬츠까지 동일한 상품이라고 주장하지 않는다.
- 실제 연결 UI: 사진 링크는 전체 면적과 모서리 12px을 유지하며 포커스 테두리가 잘리지 않게 사진 바깥에 배치한다. 출근 설명 아래 색상 링크는 14px·높이 44px 이상, 가로 간격 20px·줄 간격 4px, 설명과 간격 12px. 좁으면 링크가 줄바꿈된다. 새 창·팝업 없이 기존 상세 경로를 재사용하고 브라우저 뒤로 가기로 이전 사진 위치에 복귀한다. 사진 위에 버튼을 덮지 않는다.
- 앞뒤 연결: 단독 제품에서 실제 착용 모습으로 확장하고, 다음 컬렉션에서 선택할 옷을 찾게 한다.
- 모바일: 출근 → 산책 → 여행의 세로 순서. 사진 아래 관련 상품 버튼을 항상 보여주며 마우스 올림에 의존하지 않는다.

### 3.4 컬렉션과 추천 상품 (R04, R05)

- 목적·메시지: 마음에 든 스타일을 실제 상품 선택으로 연결한다.
- 제목 제안: “일상에 맞춰 골라보세요”. 필요한 경우 한 줄의 설명만 둔다.
- 자료: 패딩·상의·팬츠 분류 사진과 추천 상품 4종의 단독 이미지·상품명·설정 가격.
- 배치: 분류 진입은 대표 패딩의 넓은 이미지와 상의·팬츠의 작은 영역으로 비중을 달리한다. 추천 상품은 비교에 적합한 일정한 4열이다.
- 우선순위: 사진 → 상품명 → 가격 → 제공 색상. 과장된 할인·품절 임박·구매자 숫자는 넣지 않는다.
- 연결: 분류는 해당 목록, 상품은 상세, ‘전체 상품 보기’는 `/shop`.
- 앞뒤 연결: 생활 장면에서 보던 의류를 선택하게 하고 다음 브랜드 메시지에서 공통 디자인 이유를 전달한다.
- 모바일: 분류는 위아래 구성, 추천 상품은 2열. 이름은 최대 2줄 기준으로 공간을 예약하고 중요 정보는 잘라내지 않는다.

### 3.5 짧은 브랜드 소개 (R09)

- 목적·메시지: G-야크가 일상형 아웃도어를 만드는 생각을 전달한다.
- 제목 제안: “밖을 향해, 일상에 가깝게”. 본문은 “특별한 날을 기다리지 않아도 입기 좋은 옷. G-야크는 일상과 야외의 경계를 자연스럽게 잇습니다.”
- 자료: 편안한 두 사람의 생활 장면 또는 옷의 형태를 보여주는 사진. 전부 가상 브랜드의 창작 자료다.
- 배치: 단순한 사진과 짧은 문구를 배치해 상품 비교 후 화면의 밀도를 낮춘다. 브랜드 역사를 길게 만들지 않는다.
- 우선순위·연결: 브랜드 생각 → ‘G-야크 이야기’ → `/brand`.
- 모바일: 사진 다음 문구, 같은 읽기 순서. 긴 영문 슬로건으로 본문을 대체하지 않는다.

### 3.6 푸터 (R04, R09, R10)

- 목적: 마지막에 필요한 곳으로 다시 이동할 수 있게 한다.
- 내용: 브랜드명, 상품 분류, 브랜드 소개, 상품 상세에서 제공하는 사이즈·관리 안내의 위치. 실제 정보가 없는 주소·전화번호·사업자번호·SNS 링크는 꾸미지 않는다.
- 배치: PC 3개의 정보 그룹, 모바일 세로 그룹. 관련 링크와 브랜드 문구만 넣는다.
- 연결: 실제 존재하는 페이지·구간만 연결한다. 장식용 아이콘에 빈 링크를 만들지 않는다.

상품 상세의 사진은 기본 세로 배열과 썸네일 선택으로 제안한다. 여러 사진을 넘기는 장치가 필요하면 **캐러셀**, 즉 이미지를 순서대로 넘기는 장치를 사용하며 값 조절용 슬라이더와 구분한다. 자동 재생하지 않는다. 기본 시안에서는 자동 캐러셀이나 값 조절 슬라이더를 추가하지 않는다.

사이즈·관리 안내는 **아코디언**, 즉 제목을 누르면 아래 설명이 펼쳐지는 방식으로 제안한다. 별도 팝업을 중첩하지 않고 같은 화면에서 읽는다. 사이즈 표는 작은 화면에서 한 옵션의 치수를 묶어서 보여주어 전체 페이지 가로 스크롤을 만들지 않는다.

브랜드 소개는 “일상에 어울리는 형태”, “겹쳐 입기 쉬운 구성”, “밖의 시간과 연결되는 스타일”의 창작 원칙을 설명한다. 설립연도·실제 제작 공정·친환경 인증·수상·시험 결과가 존재한다고 이야기하지 않는다.

## 5. 필요한 UI와 동작 계약

| 안내 펼침 | 상세의 사이즈·관리 | 버튼/Enter/Space로 열기·닫기, 상태 알림 | 동일, 내용 높이 자동 확장 |

장바구니 드로어에는 사진·상품명·선택 옵션·수량·소계·합계가 있다. 하단에 ‘쇼핑 계속하기’, ‘주문 정보 입력’을 둔다. 장바구니 전체 페이지로 이동하는 텍스트 링크도 제공한다. 드로어가 열리면 바탕의 조작과 스크롤을 잠시 잠그고 포커스를 안으로 이동한다. 내용이 긴 경우 드로어 안에서 스크롤하며, 닫고 나면 바탕의 원래 위치를 유지한다.

메뉴와 장바구니 드로어를 동시에 열지 않는다. 담기가 성공하면 해당 동작을 알리되, 성공 알림 팝업과 드로어를 중복해 띄우지 않는다. 상품 ID·색상·사이즈·수량만 로컬 저장을 제안한다. 이름·연락처·주소는 브라우저 저장소에 기록하지 않고 주문 확인 후 지운다. 가격 합계는 정수 원 단위로 계산하며 화면마다 동일한 상품 기획값을 사용한다.

필요하지 않은 구성요소는 LNB·별도 사이드바·대형 드롭다운·페이지네이션·토글 스위치·값 조절 슬라이더·후기 입력 모달·상시 토스트다. 이번 분류 수와 상품 수, 비회원 체험에 충분한 구조를 사용한다. LNB는 하위 페이지 전용 메뉴인데 현재 분류 메뉴와 역할이 겹치므로 추가하지 않는다.

| 비활성 | 회원 항목·수량 최소값 같은 조작 불가 상태, 클릭·키보드 실행 막기; 계속 읽을 수 있는 대비 유지 |

주문 정보 확인은 현재 화면에서 처리한다. 실제 결제 승인·회원 인증·주문 API 로딩 상태를 꾸미지 않는다. 사진 실패 시 공간과 상품명을 유지하고 복구 가능한 안내를 보인다. 빈 장바구니에는 “장바구니가 비어 있어요”와 상품 목록으로 돌아가는 버튼을 둔다.

## 6. 반응형 규칙 (R11)

**반응형**은 화면 너비에 맞춰 배치를 조정하는 방식이고, **브레이크포인트**는 배치가 바뀌는 너비다. 아래 768px·1040px은 콘텐츠 폭과 한글 메뉴 길이를 바탕으로 잡은 초기 제안이다. 대표 시안에서 실제 줄바꿈과 버튼의 폭을 보고 조정한다.

| 너비 | 레이아웃·메뉴 | 글자·여백·상품 | 제품 소개·사진 |
|---|---|---|---|
| 1040px 이상 | 12열, 전체 헤더, 상세 사진/정보 2영역 | PC 글자, 양옆 48px, 목록 4열 | 좌우 설명·중앙 제품, 같은 4단계 |
| 768px부터 1039px | 8열, 모바일 메뉴, 정보 영역 폭 확인 | 제목 중간값, 양옆 32px, 목록 3열 | 제품과 설명 간격 확보, 사진 초점 유지 |
| 767px 이하 | 4열, 모바일 메뉴, 상세·폼 1열 | 모바일 글자, 양옆 20px, 목록 2열 | PC와 같은 이야기·이동·크기 변화, 설명 위아래 배치 |

사진은 생활 장면에서 얼굴과 입은 옷이 잘리지 않도록 피사체 위치를 이미지별로 기록한다. 원본을 무조건 중앙 크롭하지 않는다. PC 생활 사진은 3:2/16:9, 모바일은 4:5를 제안하되 같은 장면의 다른 크롭을 사용한다. 제품 단독은 `contain` 방식으로 전체가 보이게 한다. 상세·목록 사진은 4:5의 일관된 비율을 기본으로 제안한다.

모바일 상세의 하단 담기 영역은 약 72px과 기기의 안전 여백을 예약한다. 본문 아래에도 그만큼 공간을 넣고 마지막 정보·포커스를 가리지 않는다. 히어로에서는 같은 하단 구매 바를 중복하지 않는다. 드로어 안의 주문 버튼은 별도 내부 하단 영역을 사용한다.

320px부터 중간 너비까지 실제 한글 상품명으로 확인하고, 가로 넘침을 CSS로 숨겨 문제를 덮지 않는다. 200% 확대·큰 글자·작은 화면 높이에서 제품 고정 때문에 내용이 접근 불가능해지면 자연 스크롤로 전환한다. 모바일에서 마우스 올림 없이 모든 기능을 사용할 수 있어야 한다.

추가 움직임은 별도 `motion.css?v=12`에만 둔다. 기존 히어로·페이지 스타일·상품 동작 파일은 버전 11과 바이트 단위로 같다. 사진 내부의 확대는 바깥 사진 프레임의 타임라인을 함께 사용해 잘림과 확대가 같은 스크롤에 반응한다. 새 라이브러리·스크롤 감시 코드·추가 이미지·반복 자동 재생은 없다. 스크롤을 되돌리면 진입 연출도 되돌아간다. 기존 코드의 메뉴·장바구니 반응은 유지하며 입력 폼·옵션·오류·주문 결과를 지연시키지 않는다.

히어로의 이동 폭과 기울기는 사용자 요청에 맞춰 역동적으로 조정한다. 자동 배경 영상·반복 부유·과장된 튀는 효과·임의 스크롤 속도 변경·자동 캐러셀은 넣지 않는다. 제품은 기존 전면 이미지의 위치·크기·평면 기울기와 열린 전면 컷의 투명도 교차로 표현한다. 실제 지퍼의 이빨이 한 칸씩 열리는 물리 동작이나 3D 뒷면은 만들지 않는다. 기존 상품을 참조한 열린 모습 3컷을 AI로 제작했다. 변형과 투명도를 중심으로 구현해 레이아웃이 흔들리지 않게 한다.

AI 사진은 실제 제품·인물이 아닌 창작 자료로 내부 기록한다. 원본 광고영상 자체를 페이지 배경 영상으로 사용하지 않는다. 이미지 수·해상도·압축 방식은 실제 생성 결과를 보고 조정한다. 히어로의 기본 색상만 우선 읽고 다른 색상은 전환 전 준비, 아래 생활 사진은 필요할 때 읽으며 사진 크기와 글꼴 공간을 예약한다.

제작 후 성능 목표는 LCP 2.5초 이하(첫 주요 내용이 뜨는 시간), INP 200ms 이하(입력 반응), CLS 0.1 이하(배치 흔들림)다. 이는 [Google Web Vitals의 권장 기준](https://web.dev/articles/vitals)을 참고한 목표이며 현재 달성한 측정값이 아니다. 공개 사용자 데이터 없이 현장 지표를 확인했다고 주장하지 않는다. 대표 시안과 완성본의 로컬 측정 결과는 별도로 기록한다.

## 8. 표현·자료의 경계

사용자 화면에는 ‘데모’, ‘임시 상품’, ‘샘플’, 개발 도구명·버전·검수 설명을 넣지 않는다. 내부 문서·데이터·검수 기록에는 가상 브랜드의 설정이라는 출처를 유지한다. 후기·시험 성능·회사 연락처·사업자번호·재고 부족·인증·수상을 사실처럼 만들지 않는다.

추가로 피할 분위기는 사용자가 지정하지 않았다. 할인 배너 과다, 독자적인 과장 효과, 불필요한 카드 반복을 줄이는 것은 선택한 생활형 방향을 따른 작성자 제안이다. 구매 버튼과 모든 활성 링크는 실제로 작동해야 하며 회원 항목만 요청에 따라 비활성 처리한다.

## 9. 대표 시안의 승인 범위 (R12)

문서 확인 후 첫 제작물은 **헤더 + 히어로 4단계 + 바로 이어지는 일상 착용 섹션**이다. PC와 모바일에서 로고·사진·색상·글자·여백·색상 선택·스크롤 느낌을 비교한다. 2026년 10월 13일 사용자의 “좋아 진행해”로 이 단계의 제작을 승인받았다. 이미지·워드마크·문구·스크롤의 현재 구현값은 아래 10절에 기록하며, 사용자의 실제 화면 검토를 기다린다.

수정된 값은 이 명세와 결정 기록에 먼저 반영한 뒤 목록·상세·장바구니·브랜드 등 나머지 화면에 확장한다. 실제 검수에서는 정상 구매 체험, 미선택 옵션, 수량 오류, 빈 장바구니, 사진 실패, 모바일 메뉴·드로어 닫기, 포커스 복귀, 한글 줄바꿈, 이미지 로딩과 개인정보 미저장 여부를 확인한다. 이 문서에 기준을 작성했다는 사실만으로 실제 기능 검수가 완료된 것은 아니다.

브라우저의 CSS 스크롤 타임라인(스크롤 위치로 움직임을 진행하는 기능)을 사용했다. 예를 들어 3분의 1쯤 내리면 패딩이 왼쪽으로 크게 이동하고 설산 배경과 설명이 나타난다. 첫 설명은 진행률 13~19%에서 사라지고 제품은 17% 이후 왼쪽 이동을 시작해 글자와 겹침을 줄인다. 자동 재생·강제 스크롤·자바스크립트 스크롤 감시 없이 변형과 투명도를 바꾼다. 실제 Safari·Firefox는 미확인이다.

설명 전환은 스크롤에 연결된 투명도와 최대 24px 이동이다. 색상은 새 사진을 읽은 후 즉시 교체한다. 로딩 동안 담기를 잠시 막고, 실패 시 기존 사진·옵션과 가까운 안내를 유지한다. 제품 창 열기는 200ms·12px, 드로어 열기는 220ms·24px, 닫기는 즉시 처리한다. 버튼 바탕·호버 160ms, 누르기 0.98배. 움직임 감소 설정에서는 창도 즉시 전환한다.

도심 배경과 첫 패딩 컷이 준비된 뒤, 브라우저의 여유 시점(최대 대기 1초)에 설산·트레킹과 다른 제품 색상을 읽는다. 뒷장면 두 장을 모두 해석한 뒤 전환을 활성화하고, 대기·실패 시 도심 사진을 유지한다. 사진 위 설명은 `#4C5747`과 밝은 보호 배경을 함께 사용한다. 1440×900·390×844의 네 장면에서 글자 주변 배경을 표본 검사한 최소 본문 대비는 5.51:1이었다. 전체 프레임·모든 기기의 측정을 의미하지 않는다.

앱 미리보기의 파일 재사용 문제를 재현해 HTML이 `styles.css?v=6`, `app.js?v=6`을 읽도록 수정했다. 새 디자인·동작 파일을 배포하거나 로컬에서 갱신할 때는 두 파일의 버전도 갱신해야 한다. 실제 앱의 1265×720 표시 영역에서 도심·설산·트레킹 전환, 패딩 좌우 이동, 새로고침 후 유지까지 확인했다.

현재 화면 버전은 **17**이며 마지막 펼침 보정은15절을 따른다. styles.css?v=16, pages.css·motion.css?v=13, storefront.css·app.js?v=17, products.js?v=15를 읽는다. 검색·하트 아이콘은 icons.svg?v=14다. 열린 사진은 전면을 넓게 벌리고 소매가 바깥으로 향한 `puffer-색상-open-wide.webp`를 사용한다. 풍경 준비가 끝난 뒤 현재 색상 한 장만 읽고, 나머지 색상은 실제 선택 시 준비한다. 선택한 색상의 닫힌 컷과 열린 컷이 준비되면 한 번에 반영한다. 열린 컷만 실패하면 새 색상의 닫힌 사진을 정상 적용하고 펼침은 생략한다. 늦게 도착한 이전 색상이 현재 선택을 덮지 않는다. 상품 상세·목록의 사진은 기존 컷을 유지한다. 이전 좁은 열린 컷은 이력으로 보관한다.

실제 UI에는 데모·임시·검수·개발 문구가 없다. 가격 189,000원과 상품 이름은 가상 설정이며 내부 기록에 출처를 유지한다. 개인정보나 주문을 서버에 전송하지 않는다.

## 12. 최종 가독성·배치 보완 (화면 13)

- 상품 사진: 폭 768px 이상에서 사진 프레임의 최대 높이를 화면 높이 − 헤더 − 160px로 제한한다. 사진은 contain으로 전체 모습을 유지한다. 1440×900에서는 프레임 709×676px·아래 844px로 첫 화면 안에 표시된다. 모바일은 기존 4:5 비율 유지.
- 모바일 담기: 하단 sticky 배치를 풀고 설명 → 색상 → 사이즈·표 펼침 → 수량 → 금액 → 담기 → 디자인·관리 순서로 자연 스크롤한다. 금액과 버튼 간격 28px, 아래 최소 12px 또는 기기 안전 여백. 설명을 가리던 문제를 해결했다.
- 보조 글자: 모바일 상품 색상 설명·상세 경로는 13px, 일상 영역의 브랜드 링크는 모든 크기에서 14px. 기존 색상·위계 유지.
- 문구: ‘골라 보세요’·‘만나 보세요’·‘넓혀 보세요’·‘걸쳐 보세요’·‘맞춰 보세요’·‘적어 주세요’·‘켜 주세요’로 띄어쓴다. ‘보세요’가 혼자 다음 줄에 떨어지지 않게 앞말과 줄바꿈을 막는 공백으로 연결한다. 표의 ‘가슴 단면’·‘소매 길이’도 정리한다.
- 사진 크롭·여백·정렬·한글 상품명의 2줄 공간과 목록 4/3/2열은 유지한다. 산책 사진·브랜드 글의 겹침 없음.
- 승인한 히어로 연출 CSS와 motion.css는 수정 전 해시와 같다. 새 이미지·라이브러리·외부 서비스 없음. [최종 검수](VERIFICATION.md) 참조.

## 13. 쇼핑 경험의 실제 적용값 (화면 14)

생활형 올리브·SUIT를 유지하면서 구매 탐색을 강화했다. 코오롱스포츠의 캠페인·신상품 구성과 Snow Peak의 분류·필터·정렬에서 원칙을 가져왔으며 타사 사진·로고·문구는 사용하지 않았다. 승인한 히어로 마크업과 기본 스타일 3개 파일은 전달본 13과 바이트가 같다. 변경은 별도 storefront.css에 모았다.
