# G-야크 홈페이지 PRD

수정일: 2026년 10월 15일 · 버전: 1.6 · 상태: 전체 문구·배치 정리 및 PC·모바일 최종 검수 완료

최신 적용 범위는 화면 18이다. [쇼핑 경험 확장](EXPANSION_V14.md)과 이 문서의 마지막 절을 함께 따른다. 번호가 붙은 이전 제작 기록은 해당 버전의 이력이며 최신 범위를 제한하지 않는다.

G-야크는 일상과 가벼운 야외활동에 어울리는 남녀공용 의류와 용품을 선보이는 가상 브랜드다. 홈페이지는 제품의 디자인을 이해하고, 자신의 생활에 대입하고, 상품을 선택하는 경험을 제공한다. 구매 과정은 사이트 안에서 체험하지만 실제 결제·주문 접수·배송은 발생하지 않는다.

이 문서는 **무엇을 왜 만드는지**를 정의한다. 같은 요구사항 번호 R01부터 R12를 [디자인 명세서](DESIGN_SPEC.md)에서 사용해 모습·동작·검수를 연결한다. 확정사항의 근거와 작성자 제안은 [결정 기록](DECISIONS.md)에 구분한다.

## 1. 목적과 고객

| 항목 | 내용 | 구분 |
|---|---|---|
| 브랜드의 사업 목적 | 온라인 제품 구매를 늘리는 홈페이지 | 사용자 확정 |
| 이번 결과물의 목적 | 실제 브랜드몰 같은 완성도와 사이트 내부의 구매 흐름 체험 | 사용자 확정 |
| 핵심 고객 | 평일의 일상과 주말의 여행·산책·가벼운 산행에 함께 입을 옷을 찾는 사람 | 사용자 확정 |
| 가장 중요한 구매 이유 | 일상에도 자연스럽게 어울리는 디자인 | 사용자 확정 |
| 먼저 해결할 궁금증 | “내 일상에 어떻게 어울릴까?” | 사용자 확정 |
| 보조 궁금증 | 어떤 사이즈와 색상을 선택할지, 어떻게 관리할지 | 작성자 제안 |
| 가격 포지션 | 디자인과 가격의 균형을 갖춘 중간 가격대 | 사용자 확정 |
| 차별점을 표현할 방법 | 출근·산책·여행의 착용 이미지와 함께 입는 코디, 일관된 제품 형태 | 작성자 제안 |

고객의 나이·소득·성별 비중은 조사한 사실이 아니므로 수치로 단정하지 않는다. 유입은 SNS에서 제품을 보고 방문하거나 일상용 아웃도어를 탐색하는 상황을 설계 가정으로 둔다. 실제 방문자 수·매출·전환율은 이번 결과물의 성과로 주장하지 않는다.

## 2. 핵심 사용자 흐름

1. 홈페이지의 경량 패딩과 한글 메시지로 브랜드를 이해한다.
2. 스크롤에 따라 제품이 크게 좌우로 이동하고 기울어지는 소개를 본다. 배경은 도심 → 설산 → 트레킹 → 차분한 색상 선택 순서다. 도심·설산·트레킹에서는 닫힌 모습을 유지하고, 마지막 색상 선택 장면에서 전면과 소매가 넓게 펼쳐진 상태로 마무리한다. PC와 모바일 순서는 같다. 풍경·열린 모습은 창작 연출이며 실제 등산 성능을 증명하는 자료가 아니다.
3. 히어로에서 색상을 바꾸고, ‘제품 살펴보기’로 상품 상세에 이동한다. 선택 색상은 유지한다.
4. 착용 이미지와 옵션을 확인하고 사이즈·수량을 선택한다.
5. ‘장바구니 담기’를 누르면 드로어가 열린다. 상품·옵션·수량·합계를 확인한다.
6. 쇼핑을 계속해 함께 입을 상품을 추가하거나 장바구니·주문 정보 화면으로 이동한다.
7. 입력한 정보를 브라우저 안에서 확인하고, ‘주문 정보 확인 완료’ 화면에서 선택 내역을 본다.

다른 진입 흐름은 ‘일상 착용 장면 → 관련 상품’, ‘검색·전체·아우터·패딩·상의·팬츠·용품 → 상품 상세’, ‘브랜드 소개 → 컬렉션’이다. 회원가입 없이 모든 구매 체험이 가능하다.

**완료 화면 문구는 작성자 제안이다.** 화면에 데모·임시라는 표시를 넣지 않되 실제 결제 성공, 주문 접수, 배송 시작, 확인 메일 발송을 주장하지 않는다. 최종 버튼은 ‘주문 정보 확인’, 완료 제목은 ‘주문 정보를 확인했습니다’로 제안한다.

## 3. 페이지 구조

아래는 실제 로컬 사이트의 페이지 주소 규칙이다. 추가 서버 설정 없이 새로고침과 앞뒤 이동을 지원하기 위해 페이지·상품의 식별값을 주소에 사용한다. 개인정보를 주소에 넣지 않는다.

| 페이지 | 권장 경로 | 목적과 주요 내용 | 연결 요구사항 |
|---|---|---|---|
| 홈 | `?page=home` | 대표 제품 소개, 일상 착용 모습, 컬렉션 진입, 짧은 브랜드 소개 | R01, R02, R03, R10 |
| 상품 목록 | `?page=shop` | 24종 분류·검색·색상·사이즈·가격 조건·정렬, 사진·이름·설정 가격 확인 | R04 |
| 상품 상세 | `?page=product&id=상품ID` | 단독·착용 이미지, 색상·사이즈·수량, 코디와 관리 안내 | R05 |
| 브랜드 소개 | `?page=brand` | 브랜드의 생각과 일상형 디자인 방향을 사진과 문구로 전달 | R01, R09 |
| 장바구니 | `?page=cart` | 상품·옵션·수량 수정, 개별 삭제, 합계, 주문 정보로 이동 | R06 |
| 주문 정보 | `?page=checkout` | 입력 필드, 선택 상품과 합계, 확인 동작 | R07 |
| 관심상품 | `?page=saved` | 로그인 없이 저장한 상품 확인·개별 해제 | R04, R06 |
| 저널 | `?page=journal` | 스타일 노트 2편과 편집 컬렉션 연결 | R01, R10 |
| 저널 상세 | `?page=journal&id=글ID` | 사진·스타일 글·관련 상품 | R01, R05, R10 |
| 쇼핑 가이드 | `?page=guide` | 사이즈·관리·관심상품·정보 처리 안내 | R05, R10 |
| 확인 완료 | `?page=confirmation` | 선택 내역과 계속 쇼핑하기 | R07 |

회원가입·로그인·마이페이지는 표시용 항목이며 별도 경로나 화면을 만들지 않는다. 장바구니 드로어는 여러 페이지에서 열리는 공통 UI다.

## 4. 홈페이지 읽기 순서

| 순서 | 구간 | 고객의 판단 | 내용과 다음 행동 |
|---|---|---|---|
| 1 | 헤더 | 무엇을 찾을 수 있는가 | 상품 분류·저널·브랜드·검색·관심상품·장바구니, 비활성 회원 항목 |
| 2 | 승인한 히어로 | 대표 상품의 매력은 무엇인가 | 기존 4장면·색상 선택·상세 연결 |
| 3 | 빠른 분류·신상품·4분류 타일 | 지금 어떤 옷이 있는가 | 8종 수동 레일과 아우터·상의·팬츠·용품 진입 |
| 4 | 일상 속 착용 모습 | 내 생활에도 어울리는가 | 기존 출근·산책·여행 사진과 색상별 상품 연결 |
| 5 | 주말 편집 컬렉션 | 함께 고르기 쉬운가 | 넓은 사진·짧은 문구·8종 편집 상품 |
| 6 | 스타일 노트·최근 본 상품 | 더 알아보거나 다시 볼 수 있는가 | 실제 글 2편, 최근 기록이 있을 때 최대 4종 |
| 7 | 브랜드·푸터 | 브랜드와 필요한 안내를 찾는가 | 브랜드 이야기, 모든 분류·가이드·관심상품·장바구니 링크 |

몰입형 제품 소개 → 비교하기 쉬운 상품 → 넓은 생활 사진 → 편집 콘텐츠 → 유틸리티 순으로 정보 밀도와 휴식을 조절한다. 모든 구간을 같은 카드로 반복하지 않는다.

## 5. 요구사항과 검수 기준

| 번호 | 무엇을 만드는가 | 왜 필요한가 | 완료를 판단할 수 있는 기준 |
|---|---|---|---|
| R01 | 생활형 브랜드와 남녀공용 컬렉션 | 일상 스타일이라는 구매 이유 전달 | 출근·산책·트레킹을 서로 다른 의류·팬츠·용품 9종으로 소개. 사진/주요 링크는 상황별 3종 목록, 상품 링크는 사진과 같은 색상의 상세로 이동. 성별 메뉴를 나누지 않음 |
| R02 | 제품 중심 스크롤 히어로 | 영상의 제품 소개 경험과 10월 14일의 마지막 펼침 요청 반영 | PC·모바일 모두 도심→설산→트레킹→색상 순서, 제품 좌우 이동·기울기·확대·축소, 마지막에서만 넓게 펼쳐지고 끝까지 유지, 글자·구매 조작 겹침 없음; 열린 이미지 실패 시 기존 컷 유지, 움직임 감소에서도 모든 내용 접근 가능 |
| R03 | 히어로 색상 선택과 상세 연결 | 감상에서 구매 판단으로 연결 | 색상 이름·이미지·선택 표시가 함께 바뀌고 상세에서 같은 색상이 선택됨 |
| R04 | 24종 탐색·검색·조건·정렬 | 상품 증가 후 원하는 옷을 빠르게 찾기 | 아우터7·상의7·팬츠6·용품4, 패딩3 별도 진입. 검색 AND 조건, 색상·사이즈·가격 결합, 가격 양방향·신상품 정렬, 주소·뒤로 가기 복원, 빈 결과 초기화 |
| R05 | 상품 상세와 옵션 | 디자인과 사이즈를 확인하고 선택 | 사이즈 버튼 바로 아래에서 표를 열고 닫아도 색상·사이즈·수량·합계 유지. 표는 한 번만 제공. 옵션 확인 후 담기; 미선택 오류가 해당 옵션 가까이 표시됨 |
| R06 | 장바구니 드로어와 페이지 | 함께 입을 제품을 추가하고 구매 진행 | 담기 즉시 드로어 열림; 동일 옵션 수량 합산, 다른 옵션 구분, 수량·삭제·합계 일치 |
| R07 | 비회원 주문 체험 | 사이트 내부의 구매 흐름 완성 | 입력 검증·내역 확인·완료 동작; 실제 결제·주문 API·PII 전송/저장 없음 |
| R08 | 비활성 회원 항목 | 사용자가 요청한 쇼핑몰 외형 | 회원가입·로그인·마이페이지 클릭·키보드 실행으로 이동/입력 화면이 열리지 않음 |
| R09 | 독립 브랜드 소개 페이지 | G-야크의 개성을 깊게 전달 | 홈에서 이동 가능, 브랜드 철학·이미지·컬렉션 링크 제공 |
| R10 | 한글 중심의 완성된 표현 | 친근함과 쉬운 구매 이해 | 한글 제목·구매 안내; 영문 보조; 사용자 화면에 데모·임시 표기와 개발 설명 없음 |
| R11 | 반응형·접근성·가벼운 미디어와 히어로 외 움직임 | 작은 화면에서도 브랜드의 리듬과 쉬운 탐색 유지 | 히어로는 유지하고 착용·브랜드 사진의 펼침/확대 완화, 제목 이동, 상품 진입·호버 반응 제공. 모바일은 스크롤만으로 사용. 키보드 포커스·움직임 감소·미지원 환경에서 내용 접근 유지, 이미지 공간 예약 |
| R12 | 문서 확인과 대표 시안 검토 | 전체 제작 전 방향 확인 | PRD·디자인 확인 후 헤더·히어로·다음 섹션 PC/모바일 시안; 수정은 명세에 반영 후 확대 제작 |

R07의 PII는 개인을 알아볼 수 있는 정보라는 뜻이다. 여기서는 이름·연락처·주소 등이다. 입력값은 현재 페이지의 메모리에서만 처리하며 새로고침·종료 시 사라진다. 콘솔·로그·분석 도구·URL·브라우저 저장소·서버에 기록하지 않는다. 카드번호·계좌번호·인증 정보는 입력받지 않는다.

## 6. 콘텐츠와 상품 기획안

아래의 상품명·가격·색상·사이즈·문구는 **가상 브랜드를 위해 새로 만든 제안값**이다. 실제 판매 정보나 확인된 실측·성능이 아니다. 내부 문서와 데이터 출처에는 이 구분을 유지하고, 홈페이지에는 사용자 요청에 따라 데모 표시를 넣지 않는다.

| 상의 | 소프트 레이어 후디 | 79,000원 | 편안한 일상 코디 |
| 상의 | 에브리데이 스웨트셔츠 | 69,000원 | 기본 상의 |

위 표는 초기 9종이며 기존 식별값·가격·19개 색상 컷을 유지한다. 화면 14에서 아우터4·상의4·팬츠3·용품4를 더해 총 24종·34개 색상 컷이다. 신규 상품은 각 1색, 의류는 S·M·L·XL, 용품은 FREE다. 신규 상품별 이름·가격·색상·창작 치수의 기준은 `dist/products.js`, 생성 기록은 `assets/catalog-v14-generation.json`이다. 실제 재고량·품절 임박·할인율을 꾸며 표시하지 않는다.

준비할 자료는 로고, 상품별 단독 이미지, 대표 패딩 색상 이미지, 소재·디자인 가까운 이미지, 남녀 성인 모델의 일상 착용 사진, 코디 연결 정보, 브랜드 문구다. AI로 창작하며 다른 브랜드의 로고·제품 사진을 재사용하지 않는다. 동일 상품의 단독·착용·색상 이미지에서 구조와 디테일이 이어지는지 확인한다.

후기·판매량·수상·창립연도·인증·방수 수치·필파워·시험 온도·친환경 인증은 근거가 없으므로 만들지 않는다. 상품의 모습, 코디, 형태 중심으로 설명한다. 사이즈 안내는 가상 기획값임을 내부 자료에 기록하고 실제 측정값이라고 주장하지 않는다.

## 8. 제작 조건과 외부 서비스

새 유료 서비스·구독·소재는 구매하지 않는다. 정해진 마감일 없이 문서 → 대표 시안 → 수정 → 전체 제작 → 검수 순으로 진행한다. 기존 제공 도구의 사용 가능 범위 안에서 AI 자료를 만들고, 별도 비용이 필요한 기능을 자동으로 사용하지 않는다.

현재 단계는 전체 홈페이지의 로컬 검수 완료다. 기존 기획 폴더와 다른 프로젝트를 확인한 뒤, 외부 설치 없이 HTML·CSS·JavaScript로 구현했다. 정적 프런트엔드, 즉 브라우저에서 화면과 동작을 처리하는 구조이며 외부 서비스나 환경변수가 필요하지 않다.

외부 회원·결제·주소 검색·메일·DB·분석 서비스와 환경변수는 초기 범위에 필요하지 않다. 장바구니·선택 색상은 브라우저 내 상태로 관리하고 개인정보와 분리한다. 장바구니 저장 여부는 디자인 명세의 제안을 따른다. 공개 배포·새 계정·유료 서비스·개인정보 수집은 현재 승인 범위에 포함되지 않는다.

작업 폴더에는 기존의 다른 홈페이지와 미추적 파일들이 있다. G-야크는 `Homepage_GYak` 폴더에 별도로 준비한다. 기존 프로젝트나 파일을 삭제·변경하지 않는다. 현재 Git은 `master`, 커밋 없는 상태이며 이번 단계에서 commit·push·PR·merge·배포를 하지 않는다.

## 11. 전체 홈페이지 완료 범위 (버전 0.3)

사용자가 대표 시안에 대해 ‘1번’을 선택해 같은 방향으로 확대 제작을 승인했다. 현재 홈·상품 목록·9종 상품 상세·브랜드·장바구니·주문 정보·확인 완료의 7가지 화면을 구현했다.

- R01–R03: 기존 히어로 4단계·3색·일상 착용 섹션을 유지했다. 홈에 비중이 다른 분류 진입, 추천 4종, 브랜드 연결을 추가했다.
- R04–R05: 전체 9종, 분류별 3종. 대표 상품 3색·나머지 8종 각 2색으로 19개 제품 컷을 사용한다. 상세는 색상 유지·필수 사이즈·1–99 수량·크게 보기·사이즈 및 스타일 안내·관련 상품을 제공한다.
- R06: 여러 상품과 옵션을 함께 담고 드로어·전체 페이지에서 수정한다. 이전 대표 시안에서 담은 단일 상품도 유지한다.
- R07: 이름·연락처·우편번호·주소를 화면에서 검증한다. 결제나 주문 API는 없으며 완료는 ‘주문 정보를 확인했습니다’로 표시한다. 확인 후 장바구니는 비우고 상품 내역만 현재 화면의 메모리에 남긴다. 개인정보는 복사하거나 저장하지 않고 입력 칸을 지운다.
- R08–R11: 회원 항목 비활성, 한글 중심, 독립 브랜드 화면, 반응형·키보드·움직임 감소·이미지 실패 동작을 적용했다.
- R12: 실제 시안 승인 뒤 구현값과 검수 결과를 문서에 반영했다.

사이트 자체에는 데모·샘플·임시 표시가 없다. 실제 판매·배포는 별도 범위다. 상품명·가격·사이즈 치수는 가상 기획 데이터, 사진은 AI 창작 자료로 내부 출처를 유지한다. 상품 치수·소재 성능·영업 정보가 실물로 확인됐다는 의미가 아니다.

[PC·모바일 홈페이지 비교](PREVIEW.html), [최신 검수](VERIFICATION.md), [생성 이미지 기록](../assets/catalog-generation.json)에서 결과와 근거를 확인한다.

## 12. 최종 검수 보완 (화면 13)

사용자의 사진·글 위치, 크기·띄어쓰기·줄바꿈·가독성 검토 요청을 반영했다. R05·R11의 검수 기준에 모바일 설명과 담기 버튼의 비겹침, PC 상품 사진의 높이 조절, 의미 단위 문구의 자연스러운 줄바꿈을 포함한다. 기존 상품·가격·히어로·회원 비활성·개인정보 미저장 범위는 유지한다. 실제 결제·공개 배포는 포함하지 않는다.

## 14. 상황별 다양한 코디 소개 (화면 15)

사용자 요청: 첨부한 “평일에도, 주말에도” 영역에서 패딩만 소개하지 않고 상황에 따라 다른 상품을 보여준다. R01·R04·R05·R10·R11에 연결한다.

- 출근: 필드 포켓 오버셔츠(샌드)·필드 와이드 팬츠(차콜)·어반 데일리 백팩(차콜).

- 산책: 스탠드 하프집업(네이비)·무브 조거 팬츠(스톤)·트레일 데일리 캡(네이비).

- 주말 트레킹: 브리즈 윈드 재킷(올리브)·이지 트레일 팬츠(차콜)·필드 버킷햇(스톤).

세 사진·본문·이미지 접근성 설명을 교체하고 사진/주요 링크는 해당 3종 편집 목록(edit=commute/walk/trek), 아래 짧은 상품 링크 9개는 사진과 같은 상품·색상 상세로 이동한다. 각 코디에 상의/아우터·팬츠·용품을 함께 제시하고 패딩을 포함하지 않는다.

완료 기준: 3개의 실제 서로 다른 착용 장면, 3가지 목록에 각 3종, 9개 상품/색상 일치, 사진·코디 링크까지 합계 15개 진입 경로. PC·모바일 뒤로 가기 위치·키보드·44px 누름 영역·이미지 크롭·줄바꿈·가로 넘침 확인. 기존 히어로·24종 카탈로그·장바구니·회원 비활성 유지.

## 15. 마지막 펼침의 위치 연속성 (화면 16)

사용자 요청: 히어로 마지막 펼침에서 위치가 바뀌고 부자연스러움 수정. R02·R03·R11의 동작 기준을 보완한다. 트레킹까지의 기존 좌우 이동을 유지하고, 마지막 펼침 전80%까지 최종 위치에 도착한다. 80~100%에서는 제품 중심·크기·회전을 고정하고82~90%에서만 열린 모습과 마지막 문구가 함께 나타난다. 세 색상에서 후드·밑단 높이와 가로 중심을 맞춘다. 위로 돌아가도 같은 흐름이며 감소 설정·짧은 화면은 기존 정적 구성을 유지한다.

## 16. 사진으로 고르는 분류 탐색 (화면 17)

사용자는 히어로 바로 아래의 테두리·화살표형 가로 메뉴를 다른 형식으로 변경하도록 요청했다. R04·R10·R11: 기존 아우터·패딩·상의·팬츠·용품 진입 기능을 유지하고 실제 상품 실루엣과 짧은 이름으로 분류를 고른다. 히어로와 새 상품 영역 사이의 가벼운 빠른 탐색 역할이며, 뒤쪽의 큰 기획 분류 타일과 크기·정보량을 구분한다. 모바일에서도 다섯 분류가 모두 보여야 하고 버튼/이미지 어디를 눌러도 해당 목록으로 이동한다.


## 17. 전체 문구 정리와 최종 검수 (화면 18)

사용자 요청은 승인한 홈페이지의 전체 문구·배치를 정돈하고 PC·모바일에서 최종 확인하는 것이다. 새 페이지나 판매 기능을 늘리지 않고 기존 탐색→상품 비교→옵션 선택→장바구니→주문 정보 확인의 완성도를 높인다. (R04–R12)

- 의류·가방·모자가 함께 나오는 관심상품·장바구니·관련 상품은 “상품”으로 표현한다. 장바구니의 담기와 관심상품의 저장을 구분하고 금액 합계는 “상품 합계”로 통일한다.

- 검색 결과와 결과가 없는 상태는 현재 상황과 다음 조작을 직접 설명한다. 선택 입력에는 “(선택)”을 표시하고, 가슴 단면과 팬츠 둘레의 비교 기준을 구분한다.

- 사진 비율·모바일 읽기 순서·양옆 여백·제목 위계를 실제 한글과 24종 콘텐츠로 확인한다. 장식이나 새로운 애니메이션을 추가할 이유가 없어 승인한 움직임을 유지한다.

- 검수 기준: 19개 화면·상태×6너비=114표본에서 가로 넘침·보이는 글자 잘림·깨진 사진·이름 없는 버튼 0. 전체 기능 9묶음·11너비, 쇼핑 확장 7묶음, 모바일 조작 2너비와 별도 움직임·접근성 표본도 통과해야 한다.

- 실제 확인 결과와 제한은 [최신 검수 기록](VERIFICATION.md), 모습·줄바꿈 규칙은 [디자인 명세 17절](DESIGN_SPEC.md)에 연결한다. 기능·가격·회원 비활성·개인정보 비저장·공개 전 상태는 유지한다.
